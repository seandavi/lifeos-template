# 0003. No Intermediate Files in `/tmp`

- **Status:** Accepted
- **Date:** 2026-08-20
- **Deciders:** lwaldron

## Context and Problem Statement

The previous email scan design (`scripts/email-scan.sh`) relied on an LLM writing and executing AppleScript at runtime. That LLM frequently staged intermediate `.scpt` files under `/tmp`, which triggered workspace sandbox violations and caused silent failures. This was the single largest source of unreliable scan behavior.

Subsequent scripts also carried forward this pattern by generating temporary files in `/tmp`. We needed a clear architectural policy to prevent sandbox violations, avoid OS-level cleaning interference, and ensure all script-generated artifacts stay within project-controlled, gitignored boundaries.

## Decision

All intermediate and scratch files generated by LifeOS scripts (AppleScript temp files, scratch data, cursor state) must be written to project-controlled, `.gitignore`d directories — never to `/tmp` or system temp directories.

1. **Email Pipeline Staging:** Temporary `.scpt` extraction files must be written to `calendar/email-scans/` (e.g. `calendar/email-scans/.fetch_inbox_mail.scpt`).
2. **Hidden Dotfile Prefix:** Intermediate files should use a leading dot (e.g., `.fetch_inbox_mail.scpt`) so they do not clutter standard directory listings or Obsidian file trees.
3. **Vault-Wide Policy:** This policy applies to all Python scripts, shell scripts, and agent tools across the entire LifeOS repository.

## Alternatives Considered

- **Using `/tmp`:** Rejected because `/tmp` resides outside the workspace sandbox, is cleaned unpredictably by the operating system, and caused silent scan failures under agent execution.
- **Python `tempfile` module with default system temp:** Rejected for the same reasons as `/tmp`.
- **Dedicated `.tmp/` directory at root:** Considered, but placing scratch files inside the specific domain directory (e.g., `calendar/email-scans/`, which is already `.gitignore`d) keeps domain data self-contained and easier to clean.

## Consequences

- **Easier:** Prevents sandbox access violations during agent execution and ensures script artifacts are protected from accidental git commits via existing `.gitignore` rules.
- **Maintenance:** Scripts are responsible for managing and overwriting their own scratch files in their designated directories.
